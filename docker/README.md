# Запуск Docker

Из корня репозитория:

```sh
cp .env.example .env
mkdir -p inputs/csv parser/inputs/analytics
# Укажите в .env ALPHA_LLM_API_KEY и ALPHA_LLM_MODEL для разрешённой модели.
docker compose up --build -d
```

Приложение: http://127.0.0.1:8080/ · Swagger: http://127.0.0.1:8080/docs.

Вход: Анна Смирнова (`anna`, роль `cfo`) и Илья Воронов (`ilya`, `treasury_head`). Это моковая авторизация: токен равен ID пользователя. Она не заменяет промышленную систему прав доступа. Пока для роли нет сохранённого результата ML, интерфейс показывает общую подборку и так её называет.

`api` включает FastAPI, parser, preprocessing, ranking_module и insides. Как в `flake.nix`, установлены OCR Tesseract с `rus+eng`, полный Python path, CPU-зависимости ранжирования, настройки моделей и бюджет. `web` собирает React в несколько стадий и отдаёт его через nginx; `/api` и SVG проксируются в API. Снаружи опубликован только локальный порт веб-интерфейса. `--reload` в контейнере не используется.

`docker/requirements.lock` фиксирует полное разрешение Python-зависимостей для Python 3.12, Linux x86_64 и CPU PyTorch с SHA256. Он заменяет использование старого стартового `ranking_module/requirements.lock`, который несовместим с текущим Pydantic сервера. Обновление: `sh docker/update-lock.sh` при установленном uv. Образы используют ветки Python 3.12, Node 22, nginx 1.28; их OS-слои не закреплены digest, поэтому идентичность байтов образа не заявляется.

На ARM-хостах API собирается как `linux/amd64`, соответствуя целевой платформе lockfile. Первое использование embedding/reranker может скачивать веса Hugging Face; они сохраняются в volume `model-cache`. Веса не включаются в образ.

Тома сохраняют SQLite (`backend-data`), кеш (`pipeline-cache`), артефакты (`pipeline-output`) и веса моделей (`model-cache`), а также рабочие cache/runs/models ранжирования. Эти рабочие директории доступны непривилегированному пользователю контейнера. Исходные материалы кейса положите в `inputs/`; папка подключена только для чтения. PDF из банковского корпуса разместите в `parser/inputs/analytics/` под именами из `parser/config/analytics_manifest.json`; эта папка тоже подключена только для чтения. Для полного пайплайна с `company_id` нужен `inputs/csv/df_Uid_data_hack.csv`, либо передайте валидный `profile`/`ranking_input` в API. Для работы ранжирования используется также включённый в репозиторий `ranking_module/data/companies.csv`. Наличие моковых пользователей не означает, что профили всех компаний уже связаны с этими пользователями.

Без LLM-ключа приложение и подготовленные статьи доступны, но реальная генерация и ML-чат недоступны. Никакой ключ не попадает в Dockerfile, build args или клиентскую сборку. Используйте только модели из списка кейса. Семейство по умолчанию `GLM-5.3-Flash`, как в `flake.nix`; фактический ID модели задаёт команда.
При `ALPHA_ALLOW_UNKNOWN_COST=true` и неизвестных тарифах число 500 ₽ в `.env` не обеспечивает жёсткий контроль затрат. Для него нужны проверенные тарифы на миллион входных/выходных токенов и `ALPHA_ALLOW_UNKNOWN_COST=false`.

Полный пошаговый сценарий для жюри, включая API-запрос генерации и проверку чата, находится в [корневом README](../README.md). Для полного запуска недостаточно одного `.env`: исходный CSV и PDF не входят в Git. Статические банковские суммы на главной и три исходные статьи не доказывают работу полного конвейера.

Публичный просмотр интерфейса теперь собирается отдельно для Netlify без этого API. Команда и границы статической сборки описаны в [корневом README](../README.md). Полный Docker-режим предназначен для локальной проверки конвейера с разрешёнными входными данными и ключом модели.

Серверный API генерации:

- `POST /api/pipeline/run`: авторизованный запрос с `audience_type`, совпадающим с аккаунтом, и данными компании/материалов. Пайплайн возвращает `published_insight_ids`.
- `POST /api/insight-agent/generate`: генерация из подготовленного ranking_input; также публикует результат в ленту своей роли.
- `GET /api/insights`: подборка текущей роли. `GET /api/insights/{id}`: статья с Markdown и картинкой категории.
- `POST /api/insights/ask`: сервер берёт сохранённый объект ML, роль и переданную историю, затем вызывает ML-чат.

Проверка и эксплуатация:

```sh
docker compose config --quiet
docker compose ps
docker compose logs --tail=100 api web
docker compose down
```

`docker compose down` сохраняет тома. `down -v` удаляет базу и артефакты и не является обычным способом перезапуска.

Проверено при подготовке: схема Compose, разрешение зависимостей, локальные импорты API, тесты сервера и сборка клиента. Полная сборка образов и запуск контейнеров в текущей сессии не подтверждены: оба локальных Docker-сокета (`avito` и `default`) недоступны. Глобальный Docker context не менялся.
