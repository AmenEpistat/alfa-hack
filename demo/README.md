# Синтетический стенд

Запуск из корня: `sh scripts/start.sh synthetic`. Интерфейс: http://127.0.0.1:8081/.
Первые загрузки образов и зависимостей требуют сети. Сам сценарий не вызывает внешние сервисы.

В `fixtures/companies.csv` находятся три вымышленных профиля `U_900001`–`U_900003`, соответствующих схеме preprocessing. Основной запрос использует `U_900001`. Ни одна строка не скопирована из закрытого датасета. `sources.json` содержит десять вымышленных текстов: пять новостей и пять аналитических фрагментов. Раздел `pdf` моделирует результат извлечения текста; настоящих PDF в этом наборе нет, OCR не проверяется. Адреса в домене `.example` не являются действующими публикациями.

`request-anna.json` и `request-ilya.json` запускают сценарий для `cfo` и `treasury_head`. Учётные записи `anna` и `ilya` создаёт штатный seed API; пароль не требуется.

`runtime.py` подменяет только сбор источников, результаты нейронного ранкера и клиент LLM. Настоящие preprocessing, оркестрация, адаптер ранкера, генератор структуры, валидация цитат, Markdown, публикация и SQLite продолжают выполняться. Ответы модели фиксированы правилами; они не доказывают способность нейросети писать корректные статьи. В каждом тестовом наборе одна новость и один аналитический фрагмент: это контрактная фикстура адаптера, а не проверка ограничений настоящего ранкера на число новостей.

`app.py` — отдельная точка входа, требующая `ALPHA_SYNTHETIC_DEMO=1`. Обычный `app.main:app` не импортирует этот модуль. `/api/demo/status` раскрывает заменённые компоненты; health генератора возвращает `status: synthetic`, `llm_configured: false`. Техническое поле `generation_method: ai` остаётся частью штатного API-контракта и в этом стенде не означает живой вызов LLM; интерфейс вместо AI-метки показывает «Тестовый сценарий».

Проверка через настоящий HTTP и nginx:

```sh
docker compose -f compose.synthetic.yaml exec -T api python -m demo.verify --base-url http://web:8080
```

Проверка тех же API-действий без сети, в отдельном процессе и с временной БД:

```sh
PYTHONPATH=server server/.venv/bin/python -m demo.check_local
```

Повторная генерация использует кэш, не создавая дубликатов публикаций. Тест меняет сохранение статьи и возвращает его в исходное состояние; вопросы чата остаются в истории синтетической БД. Остановка: `docker compose -f compose.synthetic.yaml down`. Удаление тестовых томов через `down -v` — только если данные стенда больше не нужны.
