# Сценарии приёмки

## Автоматическая проверка синтетического стенда

Из корня репозитория: `sh scripts/start.sh synthetic`. Скрипт запускает API и web, затем `demo.verify` обращается к API через nginx. Ошибка проверки завершает команду ненулевым кодом; контейнеры остаются доступны для диагностики.

Проверяется последовательность для каждого из аккаунтов `anna` и `ilya`:

1. Закрытая лента без токена возвращает 401; вход выдаёт токен аккаунта.
2. `POST /api/pipeline/run` с компанией `U_900001` выполняет preprocessing CSV, воспроизводит источники и результаты ранжирования, обрабатывает фиксированные ответы модели штатным генератором и валидатором.
3. Ответ содержит `status: completed` и пять `published_insight_ids`.
4. Лента содержит статьи нужной роли; у статьи непустой Markdown и минимум два источника.
5. Сохранение меняется через API и восстанавливается; вопрос возвращает маркированный синтетический ответ со ссылками.
6. Запуск с чужой ролью возвращает 403; опубликованные ID разных ролей различаются.

`PYTHONPATH=server server/.venv/bin/python -m demo.check_local` выполняет тот же сценарий через ASGI без сокетов, проверяет сохранность после перезапуска приложения и отсутствие дубликатов при повторной генерации. Эта команда запускается отдельным процессом и не меняет рабочую БД.

## Ручная проверка интерфейса

1. Откройте http://127.0.0.1:8081/; убедитесь, что виден баннер синтетического стенда.
2. Выберите Анну. После автоматической проверки должны быть доступны пять статей с префиксом «СИНТЕТИЧЕСКИЙ ПРИМЕР».
3. Откройте статью, проверьте Markdown и список вымышленных источников. URL `.example` не обязаны открываться.
4. Сохраните статью и обновите страницу: состояние должно сохраниться.
5. Задайте вопрос в чате: ответ явно сообщает, что он фиксированный и синтетический.
6. Выйдите, выберите Илью: видна подборка казначея, сохранения другого аккаунта не переносятся.

Автоматизация кликов браузера не включена; `demo.verify` проверяет HTTP, а ручной сценарий — отображение и действия пользователя.

## Живой ML

Следуйте разделу 1 корневого README: предоставьте CSV и девять PDF, настройте разрешённую модель, запустите `sh scripts/start.sh live`, проверьте поиск и выполните генерацию для каждой роли. Критерии: непустые `published_insight_ids`, доступные статьи и содержательный ответ живого чата. `partial` требует изучения `ranking_input.gaps`, `ranking_input.errors`, `ranking_result.diagnostics`, `insights.errors` и `stop_reason`. Health или успешный синтетический тест не заменяет этот прогон.

## Остальные проверки

```sh
docker compose --profile search config --quiet
docker compose -f compose.synthetic.yaml config --quiet
npm --prefix client run build
PYTHONPATH=server server/.venv/bin/python -m unittest discover -s server/tests -v
PYTHONPATH=server server/.venv/bin/python -m demo.check_local
```

Локальные команды Python предполагают установленное окружение `server/.venv`; в контейнере используйте `docker compose exec -T api python ...`.

При дополнении комплекта 26 октября 2026 года прошли: проверка основного и синтетического Compose, синтаксиса shell-скрипта, сборка клиента с 33 тестами, 12 серверных тестов и синтетический ASGI-сценарий для обеих ролей с повторным запуском и проверкой отсутствия дубликатов.

Docker daemon недоступен в среде проверки; локальные сетевые сокеты также ограничены. Сборка образов, запуск nginx/SearXNG, ручной браузерный прогон и живой LLM не подтверждены. Это ограничение проверки, а не результат успешного запуска.
