# Модель данных и API

Источником истины для SQLite служит `server/app/models.py`; для HTTP DTO — `server/app/schemas.py` и Pydantic-модели роутеров. Актуальная OpenAPI-схема создаётся приложением и доступна на `/openapi.json`, Swagger — `/docs`, ReDoc — `/redoc`. Для живого Docker-стенда базовый адрес `http://127.0.0.1:8080`, для синтетического — `http://127.0.0.1:8081`.

| Сущность | Назначение и связи |
| --- | --- |
| `User` | Демоаккаунт; связан с сохранениями, оценками и историей вопросов |
| `Company` | Профиль компании и дополнительные JSON-данные |
| `Insight`, `InsightSection` | Публикуемая статья и поддерживаемые старые секции |
| `GeneratedInsight` | ML-контекст статьи, роль читателя, ID компании, ID запуска, JSON результата |
| `UserPreference` | Сохранение и оценка статьи пользователем |
| `QuestionHistory` | Вопрос и ответ по статье для пользователя |
| `PurchasePlan` | План закупок компании |
| Сущности ранжирования | Запуски, материалы и наборы отдельного ranking API; точные поля — в `models.py` |

Роль аккаунта выбирает ленту. Это не полная изоляция данных компаний: прямые ссылки на статьи доступны обоим демоаккаунтам. Идентификатор пользователя не является идентификатором компании.

Промежуточные данные полного конвейера также сохраняются в JSON/Markdown в `output/runs/<tenant_hash>/<run_id>/`. Они не заменяют SQLite-публикацию: интерфейс читает API ленты. Контракты профиля и генерации находятся в `preprocessing/company_profiles.schema.json` и `insides/output.schema.json`.
