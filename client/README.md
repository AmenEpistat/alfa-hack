# Client

React, TypeScript, Vite, MobX, Ant Design 6, Sass. Node.js 20.19+.

## Запуск и сборка

```sh
npm ci
npm run dev
npm run build
npm run preview
```

Команды из `client`. Обычная dev/build-сборка использует FastAPI на порту 8000; запуск описан в корневом README. В dev и preview `/api` проксируется на `http://127.0.0.1:8000`. Для другого сервера задайте `VITE_PROXY_TARGET`; для прямого API — `VITE_API_URL` (полный URL с `/api` либо адрес сервера). Переменные `VITE_*` включаются в клиентскую сборку, секреты туда не помещаются.

Для отдельного статического просмотра: `npm run build:demo && npm run preview`. `VITE_DEMO_MODE=true` при сборке заменяет HTTP-вызовы локальным адаптером с двумя подготовленными статьями и двумя моковыми аккаунтами. Сохранение/оценки хранятся в браузере, ML и чат недоступны. Только этот вариант публикует Netlify по корневому `netlify.toml`; обычный `npm run build` остаётся связанным с FastAPI.

Зависимости устанавливаются с публичного `registry.npmjs.org`: локальная `.npmrc` перекрывает пользовательский registry, lockfile содержит публичные URL. Глобальная конфигурация npm не меняется. Сборка Vite выполняется локально. Для публикации `dist` хостинг должен сам проксировать `/api` или сборка должна получить полный `VITE_API_URL`.

`npm run build` включает проверку FSD, TypeScript, тесты и production-сборку. `npm test` проверяет адаптер API, Markdown, сетевые ошибки, пользовательские настройки и расчётные примеры.

## FSD

```text
src/
  app/       # роутер, провайдеры, синхронизация MobX, стили
  pages/     # home, insights, insight, login, placeholder
  widgets/   # оболочка банка, сводка, карточки
  features/  # вход, сохранение, оценка, чат, источники, ссылки
  entities/  # session; insight с api/model/ui
  shared/    # HTTP-клиент, Markdown, маршруты, бренд, Sass
```

Между слайсами — публичные `index.ts`, импорты только в нижележащие слои. `app/providers/model-sync.ts` связывает смену пользователя с загрузкой инсайтов и настроек. Старые чистые функции и наборы примеров в model используются регрессионными тестами; рабочие страницы получают данные через API и не подменяют ошибки локальными статьями.

## API и Markdown

- `auth/users`, `auth/login`, `auth/me` — выбор пользователя и восстановление сессии.
- `insights`, `insights/{id}` — каталог и статья. `content` — Markdown; при отсутствии поля адаптер понимает прежний `sections`.
- `insights/meta/sources`, `purchase-plan`, `profile` — источники, записи закупок и профиль.
- `insights/ask` — вопрос и контекст `company_id`, `period`, `price_change_pct`.
- `preferences`, `preferences/{id}/toggle`, `preferences/feedback` — личное сохранение и оценка на сервере.
- `insights/export/purchase-plan.csv` — выгрузка с тем же Bearer-токеном.

Адаптер `entities/insight/api` переводит snake_case в поля UI: `source_ids → sourceIds`, `prepared_at → preparedAt`, `expires_at → expiresAt`, `generation_method → generationMethod`, `suggested_view → suggestedView`. Старое `minutes` игнорируется. Ошибки загрузки, отправки и сохранения видны пользователю; запрос чата отменяется при уходе со страницы.

Markdown поддерживает заголовки, списки, таблицы GFM, выделение, код и ссылки. Сырой HTML, изображения и опасные схемы URL не исполняются. Цитата `[План закупок](source:plan)` превращается в компактную кнопку рядом с утверждением: превью → панель источника → записи/публикация. Обычные HTTPS-ссылки остаются ссылками.

Источник и авторство независимы: `origin=client|bank` показывает маленький знак А, издателя «Альфа-Банк» и для клиента уточнение «данные клиента». `origin=external` сохраняет внешнего издателя. `generation_method=ai|ai_assisted` показывает «Создано AI»/«Подготовлено с AI». Для `rules|editorial` AI-подпись не рисуется.

Маршруты hash: `#/`, `#/insights`, `#/insights/{id}`. Ссылка открывает статью после мокового входа. Токен хранится в sessionStorage вкладки; сохранение и оценка — в SQLite по пользователю. История чата в UI живёт до ухода со страницы, сервер сохраняет вопросы; endpoint восстановления истории пока отсутствует.

Банковская сводка на главной остаётся статическим оформлением: в переданном API нет остатков, счетов и задач банка. Компании и закупки в начальной базе вымышлены. Реального подключения к банковским счетам нет. Для сохранённых результатов нового ML-пайплайна чат вызывает серверную LLM; для живой работы нужны ключ и модель.

Обложки категорий приходят через `category_id`, `category_name`, `cover_url`, `cover_background`. Относительный адрес `/api/assets/…` учитывает настроенный `VITE_API_URL`; при ошибке картинки остаётся прежняя SVG-обложка. Полный набор доступен на `/api/assets/insight-categories/`, реестр — `GET /api/insights/meta/categories`. Новые категории не создают статьи автоматически.


## Обновление интеграции: две роли и банковские предложения

API возвращает серверный audience_type; два аккаунта сопоставляются cfo и treasury_head. Новые материалы публикуются ML-ручками в SQLite и читаются из API, общая начальная коллекция отдельно помечена как общая. Числовой category_id сохраняется без преобразования в старые строковые cover-ID, рисунок приходит в cover_url.

Генератор insides/markdown.py передаёт отдельный Markdown-блок **Решение от Альфа-Банка**. Remark-плагин bank-product.ts группирует этот блок в aside с подписью «Предложение Альфа-Банка». Аналитические ссылки на сайт банка не подсвечиваются как реклама. Источники остаются за пределами предложения. Сырой HTML не исполняется.

Чат передаёт последние пять обменов и ожидает серверный ML-ответ до 120 секунд. История текущей страницы не является восстановленной серверной историей.
