# Client

Прототип на React, TypeScript, Vite, MobX и Ant Design 6. Стиль обновлён по двум предоставленным скриншотам главной: светлое боковое меню, компактная шапка, быстрые действия и тёмная сводка счетов с блоком задач и карты. Иконки — Lucide, иллюстрация карты сделана средствами CSS. Это учебный прототип для хакатона.

## Запуск

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Команды выполняются из папки `client`.

```sh
npm run build
npm run preview
```

## Архитектура FSD

```text
src/
  app/       # сборка приложения, маршрутизация, синхронизация моделей, вход в стили
  pages/     # home, insights, insight, login, placeholder
  widgets/   # bank-shell, bank-overview, insight-card
  features/  # вход, действия с инсайтом, уточнения, источники
  entities/  # session и insight: данные и MobX-модели
  shared/    # routing, ui/brand, стили и Sass-токены
  main.tsx   # запуск app
```

Внутри слайса код разделён по назначению: `ui`, `model`. Сегменты добавляются, когда для них появляется код. Слой `processes` не используется.

Импорты между слайсами идут через публичный `index.ts`, например `@/entities/insight`. Слой может импортировать нижележащие слои; соседние слайсы в `pages`, `widgets`, `features`, `entities` не импортируют друг друга. Внутри своего слайса используются относительные пути. Алиас `@/` указывает на `src/` и настроен в TypeScript и Vite.

`app/providers/model-sync.ts` связывает сессию с личными настройками инсайта через MobX `reaction`. Сущности `session` и `insight` независимы: при смене пользователя `app` передаёт его ID в модель инсайта. Подписка создаётся один раз при запуске и освобождается при HMR. Состояние мобильного меню принадлежит виджету `bank-shell`, фильтр сохранённых — странице `insights`.

`shared/routing` хранит текущий hash-путь и общие операции навигации. Сопоставление пути со страницей и проверка моковой сессии находятся в `app/router/AppRouter.tsx`.

Страницы загружаются по требованию через React `lazy` и `Suspense`. Код таблицы источников и модального окна не включается целиком в загрузку главной страницы.

## Ant Design

Базовые элементы интерфейса используют компоненты `antd`: `Button`, `Menu`, `Tabs`, `Card`, `Form`, `Radio`, `Input`, `Alert`, `Avatar`, `Tag`, `Empty`. Компоненты импортируются непосредственно в UI соответствующего слайса; дополнительных обёрток над каждым компонентом нет.

`app/providers/UiProvider.tsx` задаёт русскую локаль и общую тему через `ConfigProvider`: красный акцент, шрифт, размеры контролов, скругления и настройки бокового меню. Тёмная сводка счетов использует вложенную тему для контраста кнопок.

Состояния контролов и их оформление задавайте через props и theme tokens Ant Design. Sass отвечает за композицию страниц, адаптивность, банковскую сводку и иллюстрацию карты. Обычные кнопки больше не оформляются собственными глобальными классами. Иллюстрированная карточка банка и фон закрытия мобильного меню остаются специализированными HTML-элементами.

Документация: [Vite](https://ant.design/docs/react/use-with-vite/), [тема](https://ant.design/docs/react/customize-theme/).

## Sass

Стили приложения находятся в `.scss` рядом с соответствующим UI; стили библиотечных компонентов генерирует Ant Design. Общий сброс и переиспользуемые классы находятся в `shared/styles/_base.scss`, переменные — в `_tokens.scss`, миксины — в `_mixins.scss`. Глобальный вход — `app/styles/index.scss`; стили компонентов импортируются их UI-модулями. Для Sass-модулей используется `@use`.

CSS-классы глобальные, с префиксами компонентов; CSS Modules пока не применяются. Для нового компонента добавляйте стили в его слайс, а в `shared/styles` — только общие примитивы. Vite компилирует Sass через установленный пакет `sass`, дополнительный плагин не нужен.

## Проверки

```sh
npm run check:architecture # границы импортов, публичные API, циклы
npm run check              # архитектура + TypeScript
npm test                   # сценарные расчёты и ответы по подготовленным материалам
npm run build              # проверки + тесты + production-сборка Vite и Sass
```

Архитектурная проверка анализирует литеральные `import`/`export` в TypeScript и `@use`/`@forward` в Sass. Это локальная проверка правил проекта; динамически вычисляемые пути она не анализирует. Публичные Sass-модули из `shared/styles` доступны напрямую.

На главной под сводкой есть карточка «Важно для вашего бизнеса». Она открывает конкретный разбор. Постоянный вход «Бизнес-инсайты» расположен в начале светлого бокового меню. Внутри доступны сохранённые инсайты, объяснение применимости, гипотеза влияния, раскрытие основания и копирование текста. Отрицательная оценка допускает необязательное уточнение причины.

Сохранение каждого материала, скрытие карточки на главной и оценка записываются в localStorage этого браузера отдельно для каждого мокового пользователя. Данные до появления авторизации относятся к первому профилю (Анна); исходная запись сохранена. Никаких сообщений, заявок или данных на сервер не отправляется. После скрытия карточку можно вернуть. Остальные банковские разделы остаются заглушками. На мобильных меню открывается кнопкой в верхней панели.

## Лента и чтение

Лента устроена как редакционная подборка: темы «Рынок», «Закупки», «Финансы», сетка из трёх материалов с SVG-обложками и отдельное сохранение каждого. Это три ракурса одного учебного кейса по закупкам стали, а не поток новостей. Тексты и метаданные находятся в `entities/insight/model/catalog.ts`. У каждого материала свой маршрут и ссылка; старый маршрут `steel-cost` сохранён.

Слева находится статья с одной строкой действий, справа — чат без вкладок. Источники раскрываются в конце статьи. На узком экране чат идёт после статьи. Отдельные калькулятор и создание задачи удалены.

## Первый экран и срок актуальности

В начале инсайта показаны короткий вывод и срок актуальности. Расчёт и сравнение компаний можно запросить в чате. Период закупок не используется как срок годности вывода.

Метаданные срока — `entities/insight/model/validity.ts`: подготовлено 22 октября 2026, пересмотр до 29 октября включительно по московскому времени. Это вручную выбранный срок для демо, не срок из отчёта worldsteel. Досрочный пересмотр нужен при изменении цен поставщика, договоров или плана закупок. Дата видна на главной банковского кабинета и в разборе; по наступлении 30 октября статус меняется на «Срок актуальности истёк». Реальные изменения цен и договоров автоматически не отслеживаются. Правило можно узнать, задав вопрос о сроке актуальности в чате. Граница срока проверяется тестом.

## Взаимодействие с аналитикой

В разбор `#/insights/steel-cost` добавлены три сценария:

- **Разрезы и сценарии (по запросу).** Вся группа или одна из трёх компаний; октябрь, ноябрь, декабрь либо IV квартал 2026. Изменение цены от −30 до +30% пересчитывает суммы в ответе чата. Фиксированные цены не меняются. Формула: стоимость незакреплённых закупок × сценарный процент.
- **Уточняющие вопросы.** Свободное поле для вопросов про расчёт, компании, фиксацию, следующие шаги и источники. Enter отправляет вопрос, Shift+Enter добавляет строку. Поле закреплено внизу панели, переписка прокручивается внутри неё. В вопросе можно указать компанию, период и процент. Указанные условия используются для последующих вопросов этого диалога. История сохраняет контекст каждого ответа; очистка истории сбрасывает условия.
- **Проверка основания.** Настоящая ссылка на [worldsteel Short Range Outlook, October 2026](https://worldsteel.org/media/press-releases/2026/worldsteel-short-range-outlook-october-2026/), просмотр девяти исходных записей учебного плана, CSV и допущения. Обзор описывает спрос, он не доказывает рост закупочных цен. Компании и закупочный план вымышлены.

Модель данных и расчёт — `entities/insight/model/analysis.ts`, состояние разреза — `analysis-store.ts`. Ответы формируются детерминированными правилами в `answer.ts`, без LLM, сетевых запросов и серверной аналитики. На неподдерживаемые темы, недоступные периоды, вероятность изменения и прибыль предусмотрен ответ о нехватке данных. Это функциональный демонстрационный сценарий; универсальный диалог на реальных отчётах ещё требует бэкенда, поиска по документам и модели.

История вопросов живёт в памяти страницы и очищается при уходе с неё. Условия расчёта сбрасываются при новом диалоге и смене моковой сессии. В отличие от избранного история и разрез не записываются в localStorage. «Копировать текст» копирует вывод, срок актуальности и источник. Ссылка «Поделиться» ведёт на сам инсайт; условия переписки в неё не включаются.

Проверочный пример: вся группа, IV квартал, +10% → план 129 млн ₽, без фиксации 63,9 млн ₽, изменение +6,39 млн ₽. «Северстрой Подряд», октябрь, +10% → +240 тыс. ₽. Для инфраструктуры за октябрь при +15% → +1,08 млн ₽. Эти суммы проверяются тестами вместе с отрицательными сценариями и отказами при нехватке данных.

## Ссылки и моковый вход

- Кнопка «Поделиться» на главной и в разборе открывает модальное окно со ссылкой вида `https://адрес-прототипа/#/insights/steel-cost`. Её можно скопировать и отправить самостоятельно.
- На текущем локальном запуске пример: `http://127.0.0.1:5173/#/insights/steel-cost`. На другом устройстве localhost указывает на другое устройство; для отправки ссылок другим людям нужен общий адрес хостинга или отдельно настроенный сетевой доступ.
- Без сессии открывается выбор демопользователя. После входа исходный маршрут сохраняется: ссылка ведёт сразу в соответствующий разбор.
- Сессия хранится в sessionStorage вкладки и переживает перезагрузку. Кнопка «Выйти» завершает её; для просмотра от другого человека выберите второй профиль на экране входа.
- Используются hash-маршруты: главная `#/`, подборка `#/insights`, конкретный инсайт `#/insights/steel-cost`. Работают перезагрузка, «Назад/Вперёд» и неизвестный ID (страница не найдена). Перезаписи URL на хостинге не нужны, так как путь находится после `#`.
- Это клиентская имитация входа на учебных данных; реальной серверной проверки прав доступа нет. Состояние не синхронизируется между устройствами.

Компании, закупочные суммы и изменение цены — учебные примеры. Публичный рыночный источник доступен по ссылке; реальные профили клиентов, планы закупок, API, генерация инсайтов и серверная аналитика пока не подключены. Данные прототипа нельзя интерпретировать как реальные показатели банка или результат эксперимента.

Замечания к метрикам команды и план измерения: [docs/metrics-review.md](../docs/metrics-review.md).
