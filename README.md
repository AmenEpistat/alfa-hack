# Альфа-Бизнес · персонализированные бизнес-инсайты

React + TypeScript + MobX + Ant Design + Sass (FSD). FastAPI + SQLite. Модули обработки: `preprocessing → parser → ranking_module → insides`.

## Два способа проверки

### Netlify: посмотреть интерфейс без сервера

Подключите этот GitHub-репозиторий в Netlify. Корневой [`netlify.toml`](netlify.toml) задаёт базовую папку `client`, команду `npm run build:demo` и публикацию `client/dist`. В настройках Netlify не нужен API-ключ. После сборки откройте выданный Netlify URL, выберите один из двух аккаунтов и перейдите к «Бизнес-инсайтам».

Этот статический вариант содержит **две подготовленные статьи** (`steel-cost` и `price-fixation`), переходы по ссылкам, источники и локальное сохранение/оценки в браузере. Два аккаунта видят одну и ту же подборку: эта сборка показывает интерфейс, а не результат ролевого ML. Чат и генерация отсутствуют; секреты модели не попадают в браузер. Три статьи из `server/app/seed.py` используются только при запуске полного API.

Проверить ровно Netlify-сборку до публикации:

```sh
npm --prefix client ci
npm --prefix client run build:demo
npm --prefix client run preview
```

Затем откройте http://127.0.0.1:4173/. Netlify публикует только содержимое `client/dist`; данные Python/SQLite на статическом сайте не исполняются. Если проект уже подключён к Netlify, после push проверьте настройки сборки: Base directory `client`, Build command `npm run build:demo`, Publish directory `dist`. [Рекомендации Netlify для Vite](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/).

### Локально: проверить полный backend и ML

Нужны Docker с запущенным движком, Compose v2, доступ к публичным реестрам пакетов и свободный порт 8080. Из корня репозитория:

```sh
cp .env.example .env
mkdir -p inputs/csv parser/inputs/analytics
docker compose up --build -d
docker compose ps
curl -fsS http://127.0.0.1:8080/api/insight-agent/health
```

Откройте http://127.0.0.1:8080/ и выберите Анну Смирнову или Илью Воронова. API: http://127.0.0.1:8080/docs. Без ключа модель не подключена: доступны главная, общая подборка из трёх подготовленных статей, источники, сохранение и ссылки. Ответ `"llm_configured":false` в проверке выше подтверждает отсутствие живого чата.

Первый запуск может быть долгим: Docker собирает Python/Node-образы, а ранжирование при первом обращении отдельно загружает веса моделей. Если сервис не поднялся, смотрите `docker compose logs --tail=100 api web`. Контейнерная сборка здесь не была проверена на работающем Docker-движке; перед отправкой ссылки жюри её нужно проверить на целевом хосте.

### Чтобы заработали генерация и чат

1. Получите у организаторов **API-ключ и точный ID разрешённой модели**. Заполните в локальном `.env` `ALPHA_LLM_BASE_URL`, `ALPHA_LLM_API_KEY`, `ALPHA_LLM_MODEL`. Подписка ChatGPT сама по себе эти значения не даёт. Ключ не добавляйте в Git.
   Лимит `ALPHA_DAILY_BUDGET_RUB=500` не является жёстким локальным ограничением при исходном `ALPHA_ALLOW_UNKNOWN_COST=true`: цены токенов неизвестны. Для учёта расходов задайте тарифы `ALPHA_INPUT_RUB_PER_MILLION`, `ALPHA_OUTPUT_RUB_PER_MILLION` и `ALPHA_ALLOW_UNKNOWN_COST=false`; реальные тарифы подтвердите у провайдера.
2. Передайте разрешённые входные данные: CSV `inputs/csv/df_Uid_data_hack.csv` и банковские PDF в `parser/inputs/analytics/` под именами из `parser/config/analytics_manifest.json`. Эти папки не входят в Git. Без них полный конвейер не воспроизводится; проверяемый тестами JSON из `ranking_module/tests/fixtures` — синтетический пример, не готовая публикация.
3. Перезапустите API: `docker compose up -d --force-recreate api`. Проверка `curl -fsS http://127.0.0.1:8080/api/insight-agent/health` должна показать `"llm_configured":true`. Это подтверждает наличие настроек, **не** успешный ответ модели.
4. Запустите конвейер для ID компании из переданного CSV. Пример для Анны (замените `U_ID_FROM_CSV`):

```sh
curl -fsS -X POST http://127.0.0.1:8080/api/pipeline/run \
  -H 'Authorization: Bearer anna' \
  -H 'Content-Type: application/json' \
  -d '{"action":"run","audience_type":"cfo","company_id":"U_ID_FROM_CSV","allow_pdf_processing":true}'
```

Для Ильи используйте `Bearer ilya` и `"audience_type":"treasury_head"`. Генерация опубликована только если ответ содержит непустой `published_insight_ids`; затем обновите страницу. Чат есть у опубликованных инсайтов с сохранённым ML-контекстом. Проверьте один реальный вопрос в каждой роли. При ошибке смотрите `docker compose logs --tail=100 api` и поле `error` в ответе. Наличие ключа и файлов само по себе не гарантирует пять прошедших проверку инсайтов: результат зависит от источников и модели.

Текущие три статьи берутся из `server/app/seed.py`; на чистой установке они не персонализированы. Чтобы дать жюри готовый живой сценарий, команде нужно **до сдачи** выполнить пункты выше, проверить ответы и предоставить организаторам доступ к настроенному сервису либо разрешённые входные файлы и ключ отдельно от репозитория.

Перед передачей репозитория проверьте, что `README.md`, `netlify.toml`, `compose.yaml`, `docker/`, `server/`, `client/` и `.env.example` действительно закоммичены и отправлены. Локальные неотслеживаемые файлы жюри при клонировании не получит. `.env`, `backend.db`, `inputs/` и `parser/inputs/` в Git не добавляйте; для полного AI-сценария их нужно предоставить разрешённым способом отдельно.

Для локальной разработки нужны Node.js 20.19+ и Python 3.12:

```sh
python3.12 -m venv server/.venv
server/.venv/bin/python -m pip install -e ./server -e ./parser
server/.venv/bin/python -m uvicorn app.main:app --app-dir server --reload --host 127.0.0.1 --port 8000
```

В другом терминале:

```sh
cd client
npm ci
npm run dev
```

Для выполнения ранжирования вне Docker дополнительно установите `ranking_module` и его CPU-зависимости. Nix-вариант описан в `flake.nix`; конфигурация Docker учитывает его Python paths, OCR, модели и кеши.

## Аккаунты и данные

Два тестовых пользователя: `anna → cfo`, `ilya → treasury_head`. Сервер определяет роль по аккаунту. Подготовленные результаты ML сохраняются в SQLite и попадают в подборку своей роли. Ссылка на отдельный инсайт открывается и под вторым аккаунтом; его персональная лента при этом остаётся своей. До первой генерации доступна общая коллекция; она не выдаётся за ролевую генерацию. ML не запускается автоматически при каждом входе.

Авторизация моковая; производственная аутентификация и полноценные права на компании не реализованы. Банковские остатки и задачи на главной — статическое оформление. Предоставленные обезличенные данные и статьи не доказывают реальную интеграцию с банковскими системами. Для живой генерации и ML-чата требуется отдельно настроенная разрешённая LLM.

## Проверки

```sh
npm --prefix client run build
PYTHONPATH=server server/.venv/bin/python -m unittest discover -s server/tests -v
docker compose config --quiet
```

Тесты API используют отдельную временную SQLite. Вызовы ML в интеграционных тестах заменены контролируемым результатом; они проверяют передачу роли, публикацию, разделение подборок и показ Markdown, а не качество реальной модели.
